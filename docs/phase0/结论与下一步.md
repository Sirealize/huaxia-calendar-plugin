> 回答一个问题：**这个项目要不要继续？**
> 依据：三个并行 Spike 的实测证据（宿主 / 算法 / 内容层），全部产物在仓库内可复现。
> 日期：2026-11-18
>
> **更新（同日）：用户已拍板「继续 + 全原创/公有领域内容」，M0′ 已按本文第四节范围交付完毕。**
> 交付证据：`npm test` 72 项全绿（核心 44 + 内容 8 + UI 20）、`npm run build/verify/typecheck` 全绿、
> tarball 在隔离实例实装后侧栏出现「华夏日历」并正确渲染月历与今日一屏（截图见 README）。
> 详见文末「八、M0′ 交付记录」。

## 一、结论

**继续。但不要按原规划继续 —— 换形态、换顺序、砍内容。**

| 判断 | 结论 |
|------|------|
| 项目**技术上**是否可行？ | ✅ **可行，且比规划预期更好**。宿主 API、构建链、安装、Token 数据、农历算法五项全部实测通过，规划里最大的 P0 风险可以关掉 |
| 项目**需要多少工程**？ | ✅ 比规划小得多：核心算法层已经写出来了（44 测试全绿），最小可装版本的主要工作量是 UI + 打包，不是算法 |
| 项目**真正贵**在哪？ | ⚠️ **内容层**。365 天历史叙事必须自撰（公开数据集许可证不可用），约 30–40 小时编辑工时，且无法用工程手段压缩 |
| 最大的**未验证假设**是什么？ | 「开发者愿意在 AI 编码工具里常驻一个日历」——这个产品假设，一天都还没验证过 |
| 因此建议 | **先花一周做出"能装、能看、能跑"的 M0′ 版本，用它验证产品假设；内容只做 30 天样板，全量内容等验证通过再投** |

**一句话**：技术侧已经没有未知数了，剩下的都是"要做多少内容 / 值不值得做内容"的商业判断。所以**先做一个便宜的可体验版本，再决定要不要投入内容工程**——而不是按原规划花 6-8 周做完再验证。

| Spike | 问题 | 结论 | 证据 |
|-------|------|------|------|
| **A · 宿主** | 作为 DeepSeek Harness 插件能不能装上 UI？Token 数据拿不拿得到？ | ✅ **能。** slot 注册契约确认（全机 113 个 slot），第三方插件（`dsh-context`）已用同款方式接管主面板；我们构建的最小插件已被宿主发现并进入启动图（`__DSH_BOOT__.entries`，bundle 返回 200）；Token 四桶可自动读取 | [宿主可行性.md](./宿主可行性.md)（361 行）+ [`spikes/dsh-hello/`](../../spikes/dsh-hello/)（可复现：build → verify → typecheck 全绿） |
| **B · 算法** | 农历/节气/干支能不能纯本地算准？ | ✅ **能，且已实现。** vendor `lunar-javascript@1.7.8`（MIT），2026 年 24 节气与香港天文台官方数据**分钟级一致**，10 年逐日遍历通过；44/44 测试通过，整包 gzip 105 KB | [核心算法可行性.md](./核心算法可行性.md)（582 行）+ [`packages/core/`](../../packages/core/)（`npm test` → 44 pass） |
| **C · 内容** | 365 天历史叙事能不能"抓个数据集就完事"？ | ❌ **不能。** 两个主流开源「历史上的今天」数据集，一个无许可证，一个是 MIT 外壳包着维基 CC BY-SA + 百度百科内容，**都不能随包分发**。必须自撰 | [内容层可行性.md](./内容层可行性.md) |

### 三个"意外收获"（规划里没有的好消息）

1. **Token 数据能自动采集**，不是只能手动录入。规划风险表里「Token 无法自动获取导致功能价值打折」这条 P1 风险**直接不成立**，F07 从"手动/CSV"升级为"自动采集 + 补录"。
2. **开发插件不需要克隆 DSH 源码仓库**。构建产物契约只有一条（`window.__ModuleLoader__.load({id, factory})`），开发依赖在 npm 上都齐，20 行 wrapper 即可出包——这意味着**改造成本极低**，一次投入可长期维护。
3. **核心算法层已经完成**。`@shishu/core` 不是纸面设计，是能跑、有测试、与官方天文数据对过账的代码。M0′ 不需要在算法上再花时间。

## 三、必须修正的规划假设（6 处，都有实测依据）

> 下表如需逐条溯源，见 [宿主可行性.md 第六节](./宿主可行性.md)。

| 编号 | 规划原判断 | 实测结论 | 修正后 |
|------|-----------|---------|--------|
| **A1** 嵌入形态 | 用户脚本注入 + 独立悬浮窗兜底 | ❌ 用错路径。DSH 有原生插件机制，第三方已在大规模使用 | **DSH 原生插件（bundle + slot）为主**；Tauri 只兜 F11 的 OS 级置顶；**用户脚本注入方案删除** |
| **4.2** 技术选型 | Web Components（Lit/Stencil） | ❌ slot 组件必须是 React（React 由宿主提供），Web Components 拿不到 props/hook 契约 | **核心层 = 零框架纯 TS（已完成）；UI 层 = React 18** |
| **F05** Git 一键安装 | ≤3 条命令完成安装 | ❌ git 安装必先失败一次再授权（`prepare` + `allowBuilds`），≥5 步 | **主推 tarball（内网）/ npm（公网）**；git 作为源码渠道写清 5 步并锁 commit sha |
| **F06** 离线可用 | 所有功能断网正常 | ⚠️ **运行时**成立；**安装**不成立（git 首次需网络） | 离线限定为**运行时**；离线安装走 tarball |
| **F07 / A4** Token | 手动录入 + CSV | ✅ 可自动读取（输入/输出/cacheRead/cacheWrite 四桶） | **自动采集 + 手动补录** |
| **F11** 四角悬浮置顶 | 宿主 overlay API + Tauri 兜底 | ⚠️ DSH 内只有**页面内浮层**，做不到跨窗口置顶 | DSH 内做页面内浮标；**OS 级置顶必须靠独立桌面版** |

**另外新增一条规划没识别的风险**：**DSH 版本漂移**。运行时是 `0.2.2-rc.1`，而 npm 上已发到 `rc.4`（2026-11-17 还在推）。slot 名与 `SlotMap` 是版本契约，会变。缓解：`engines.dsh` 精确锁版本 + 席位名收敛成一张映射表 + CI 跑 `typecheck`/`verify`（本次 spike 就是现成的 CI 骨架）。

## 四、建议的 M0′：一周内做出"能装、能看"的版本

### 4.1 范围（做什么 / 不做什么）

| 做 | 不做（推到 M1+） |
|----|------------------|
| ✅ DSH 原生插件包（`sidebar.panellist` + `main` 全局面板） | ❌ 365 天全量内容（只做 30 天样板） |
| ✅ 月历视图 + 公历/农历双轨 + 节气标注 + 当天高亮 | ❌ 每日卦象（合规风险最高、价值待验证） |
| ✅ 今日一屏：公历、农历、干支、节气、历史一条 | ❌ Token 自动采集的"按天精确版"（M0′ 先不做，M1 再做） |
| ✅ 30 天精选历史叙事（文明史视角、过合规清单） | ❌ 任务清单 / 日报 / 主题皮肤 |
| ✅ tarball 分发 + 安装脚本（内网可装） | ❌ VS Code 适配、Tauri 桌面版 |
| ✅ 席位映射表 + CI typecheck 骨架（防版本漂移） | ❌ CSS Modules 主题管线（M0′ 先用 CSS 变量 + 内联样式） |

### 4.2 验收标准

1. 在内网/离线环境，按 README 二条命令装上，重启 GUI 后左栏出现「华夏日历」入口。
2. 点进去：月历可翻月，当天高亮，每格显示农历日与节气，无错位。
3. 今日一屏：历史叙事一条，农历/干支/节气正确（与 `@shishu/core` 断言一致）。
4. 断网状态下全部功能正常。
5. `npm test` 全绿 + `npm run typecheck` 对 `0.2.2-rc.1` 类型 exit 0。

### 4.3 为什么是一周而不是 6-8 周

- 算法层已完成 → 省掉 M1 里程碑
- 宿主契约已验通 + spike 已有可复用骨架 → 省掉 Phase 0 剩余与 M3 适配器的探索期
- 内容只做 30 天 → 省掉 30–40 小时
- **剩下的只是"把一个 React 面板画出来"**，这是确定性工作

### 4.4 唯一实质工程缺口

**CSS Modules / 图片资源管线未解决**（DSH 的 tsdown 预设没发布成 npm 包）。M0′ 用 CSS 变量 + 内联样式绕过（1 天内可接受）；要做 F12 主题皮肤（水墨/青铜）时必须自研等价构建插件，估 **1–2 人日**。这是目前唯一"想做漂亮就得额外付钱"的地方。
