# 内容发布审核清单

> 适用对象：`packages/content-l1/**` 的「每日文明史叙事」条目，以及未来任何随包分发或在线推送的文本内容（卦象解读、节令文案、专题扩展包）。
> 权威依据：`docs/evaluation/内容层可行性.md`（第三节筛选标准、第四节合规边界）与 `packages/core/src/data/schemas.ts`（许可证铁律）。
> 原则：**准确性优先于丰富度；不确定宁可不写。年份写错是产品事故。**

---

## 0. 一页速查（每条内容都必须全部打勾）

- [ ] 这是**原创整理**或**公有领域**内容，没有 CC BY-SA、维基正文、百度百科正文
- [ ] `source` 已填（自撰写「原创整理」），`license` 只取 `self-authored` / `public-domain`
- [ ] `retrievedAt` 已填 ISO 日期；引用公有领域原文时 `sourceUrl` 已填或注明版本出处
- [ ] 年份经过**至少两个独立来源**交叉核对，其中至少一个是权威来源
- [ ] 日期口径已确认：`dateKind` 填 `exact`（确为当日，`summary` 写明日期）或 `period`（文明坐标，`summary` 不得出现公历月日）；跨日事件已按原始记录归档
- [ ] 无预测、占卜、吉凶、宜忌、财运、姻缘、健康类表述（见 §3 红线词表）
- [ ] 民族、宗教表述使用规范名称，不评价教义，不涉及敏感事件（见 §4）
- [ ] `summary` 60–140 字，`title` 8–20 字，说清「哪年 + 发生了什么 + 为什么值得记一笔」
- [ ] 不写帝王家事、宫廷斗争、战争细节、当代政治评价；无煽情、无夸张断言
- [ ] `region`（`china` / `world`）、`origin`（如「中国·北宋」「欧洲·意大利」）、`dateKind`（`exact` / `period`）均已填
- [ ] 符合「选题配比」硬约束（每天 2 中华 + 1 世界 / 全包中华 ≥2/3 / 世界多样且美国 ≤5 / 古代 ≥30）——见 §5
- [ ] `node --test` 与 manifest 构建全部通过（见 §7）

## 1. 许可证合规（发布闸门，一票否决）

| 项 | 要求 |
|----|------|
| 允许的 `license` | 仅 `self-authored`（原创文案）与 `public-domain`（已过版权保护期的原文，如《周易》经文） |
| 禁止的许可证 | `CC-BY-SA-4.0`（相同方式共享会传染整个内容包），以及 `unknown`、空白、无许可证来源 |
| 禁止的内容来源 | 维基百科/维基数据正文、百度百科、互动百科等百科站正文；任何无 LICENSE 的「历史上的今天」数据集；受版权保护的白话译本 |
| 允许的参考来源 | 官方机构与国家级媒体、学术机构与权威辞书、公有领域古籍原文（仅可引用原文，白话解释必须原创） |
| 来源字段 | `source` 必填；`sourceUrl` 在引用网页/数据库时填写；`retrievedAt` 必填 ISO 日期 |
| 署名义务 | 仅 CC 许可需要 `attribution`；本项目不使用 CC 许可，`manifest.attribution` 仍需声明整体为 self-authored |

> 判定不下来的，按「不能用」处理。违反本节的条目不得进入发布包，`validateContentPack()` 会阻断。

## 2. 年份与史实核实流程（准确性红线）

1. **列候选**：先把「日期 + 年份 + 事件 + 一句话意义」写成草稿，不确定的候选直接丢弃，不要先写正文再补年份。
2. **双源交叉**：至少 2 个**相互独立**的来源；其中至少 1 个为权威来源（国家部委/官方机构、国家级媒体、高校或学术机构、权威辞书、当事人档案）。两个来源不能互相转抄（例如两个聚合站同抄一条维基不算双源）。
3. **确认日期口径**：区分事件发生地当地时间与 UTC；境外事件可能跨日。本产品按北京时间展示，归档仍以**事件原始记录日期**为准；若两种口径会落在不同日期，选择无歧义的一天，或在 `summary` 内注明口径（如「当地时间」）。
4. **置信度自评**：
   - 高：能复述来源与关键细节，来源间无冲突 → 可发布
   - 中：方向确定但日期/细节需再核 → **不得发布**，继续核或换条
   - 低：凭印象 → **直接换条**
5. **记录核校证据**：审核人在发布记录里写下核对过的来源（链接或书名+版次+页码），而不只是打勾。
6. **二次独立核对**：内容作者与审核人不得是同一人的「自我确认」；发布前由另一人独立复核年份。

**典型易错点**：把「发明完成年份」写成「专利批准日」；把「首次公开演示」写成「发明日」；把 UTC 日期直接当北京时间；把「某年」当成「某月某日」；将传记生日当作事件日。

## 3. 合规红线词表（占卜 / 预测类，禁止出现在任何内容与 UI 文案）

| 禁止类别 | 禁止词/表述（含近义变体） | 允许的替代表述 |
|----------|--------------------------|----------------|
| 吉凶宜忌 | 宜、忌、吉、凶、大吉、大凶、凶兆、祥瑞断语、今日宜/忌 | 仅陈述历史事实与文明史意义 |
| 运势预测 | 运势、时运、开运、转运、好运、厄运、命中注定、预示、征兆 | 不预测个人未来 |
| 财运 / 姻缘 | 财运、进财、破财、姻缘、桃花运、正缘、合婚、感情运 | 不涉及个人事项 |
| 健康 / 学业 | 健康运、疾病预测、考试运、升迁运、官司运 | 不涉及个人事项 |
| 术数操作 | 占卜、算命、摇卦、起卦、解卦、抽签、看相、风水、化解、消灾、本命年禁忌 | 传统文化知识介绍；明确注明「非预测建议」 |
| 伪科学断言 | 「科学证明」式玄学、必然因果断言、绝对化预测 | 使用「据记载」「史料表明」等可核查表述 |

> 说明：卦象（F08）不在 M0′ 范围；未来若上线，只允许「卦名/卦画/卦辞/爻辞原文 + 原创义理解读 + 常驻免责声明：传统文化知识，不构成任何预测或建议」，且必须保留 `compliance.prophecyEnabled = false` 开关的降级路径。

## 4. 民族与宗教表述规范

- 使用**规范全称**：行政区划、民族名称、宗教名称使用国家规范表述，不使用旧称、俗称或贬称（如不用「回教」「穆民」等旧称指代伊斯兰教/穆斯林）。
- **不评价教义**：只做历史与文明史层面的客观陈述，不对宗教教义作真伪、高低、优劣判断。
- **不涉及敏感事件**：不写民族冲突、宗教冲突的细节与归因；不转载境外对民族宗教事务的评论。
- **不搞身份标签**：不以民族、宗教身份给人物贴标签；涉及多民族共同历史时使用「各民族」等规范表述。
- **古籍引用**：引用古籍原文可保留历史用语，但须注明出处与时代背景，不得借此输出歧视性或贬损性表述。
- **地名与称谓**：历史地名可保留，但需与今地名对应清楚；涉及边界、领土表述严格使用国家规范用语。
- 拿不准的敏感条目：**换条**，不要试探边界。

## 5. 选题配比（v0.3.0-A 起的硬约束）

> 触发背景：用户反馈「历史叙事当天需要一个轮播的古今中外，不能只有美国什么事，华夏中华文明要体现出来」。
> 原 30 条一天一条且偏西方，因此改为「每天 3 条、以中华文明为主体、兼及世界」。
> 以下配比是**发布级硬约束**，已由 `packages/content-l1/test/content-pack.test.ts` 逐条断言，不达标 `node --test` 直接失败。

### 5.1 每天 3 条，30 天共 90 条

| 规则 | 要求 | 校验方式 |
|------|------|----------|
| 每日条数 | **恰 3 条**（供当天轮播） | 测试按公历月日分组断言 |
| 每日中华条目 | **≥2 条**（`region: "china"`） | 逐日断言 |
| 每日世界条目 | **≤1 条**（`region: "world"`） | 逐日断言 |
| 全包中国占比 | **≥2/3**（90 条中国 ≥60 条，当前 60 中华 + 30 世界） | 交叉相乘断言，避免浮点误差 |
| `id` | `he-<MMDD>-<序号>`，同日序号恰为 `001/002/003` | 逐日断言 |
| 日期口径 | 每条显式 `dateKind`（`exact` / `period`），且**每天 ≥1 条 `exact`** | 见 §5.4 |

同日展示顺序由 `@shishu/core` 的类型契约与内容层保证：**`china` 在前，其次 `weight` 降序，最后年份升序**；
`weight` 建议区间：中华古代 90–100、中华近现代 70–89、世界 40–69。`getEventsForDate` / `getEventForDate` 的导出名与排序语义是 UI 依赖，**不得改动**。

### 5.2 世界条目要多样，不许扎堆美国

- 30 条世界条目必须覆盖：**欧洲、亚洲（日本 / 印度 / 东南亚）、阿拉伯、波斯（伊朗）、非洲、拉美、大洋洲**，测试按 `origin` 的「板块·国家/地区」前缀断言板块齐全。
- **美国题材全包 ≤5 条**（测试按 `origin` 或 `summary` 指向美国统计）。同题材取舍时**优先非美国选题**，避免出现「到处是美国」的观感。
- `origin` 统一写成「板块·国家/地区」：如「欧洲·意大利」「亚洲·日本」「非洲·南非」「拉美·墨西哥」「东南亚·马来亚」「阿拉伯·海湾」。
- 世界条目同样遵守 §2 的年份核实与 §3、§4 的合规边界，并优先选科技、思想、制度、艺术类而非战争流水账。

### 5.3 古今平衡

| 规则 | 要求 | 当前 |
|------|------|------|
| 中国古代（先秦—清，1840 年前） | **≥30 条** | 47 条 |
| 1840 年后近现代 | **≤40 条** | 38 条 |

- 选题向「文明含量」倾斜：诸子思想、制度首创（郡县、科举、法典）、四大发明、天文历法、医学、农学、水利工程、丝路交流、瓷器、造船、数学、营造、类书字典等。
- 不要写成政治史/战争史流水账；帝王家事、宫廷斗争不做选题。
- 每天的两条中华条目尽量「一古一今」或「一古一古」，避免整天都是近现代。

### 5.4 日期口径：`dateKind` 分 `exact` / `period` 两类（不许撒谎）

中国古代纪日为干支/农历，无法逐年换算到公历月日。因此**每条都必须显式标注 `dateKind`**，按两类口径分别展示；缺省按 `period` 处理（宁可标注为文明坐标，也不谎称「今天」）。

| `dateKind` | 含义 | UI 展示口径 | 撰写要求 |
|------------|------|-------------|----------|
| `exact` | 事件**确实发生**在该公历月日，可核实 | 「历史叙事 · 历史上的今天」 | `summary` 必须写明当日日期（如「1982 年 12 月 4 日」），这是「今天」的可信度来源 |
| `period` | 只以「年份 + 朝代」入档的**文明坐标**，`solar` 月日仅作轮播归档位 | 「华夏文明坐标 · 朝代 · 年份」 | `summary` **不得出现任何公历月日表述**（`X 月 X 日`），不得暗示事件发生在当天 |

验收规则（`packages/content-l1/test/content-pack.test.ts` 已逐条断言）：

- 每条都必须显式填写合法 `dateKind`；`validate.ts` 对非法值报 error、对缺失报 warning。
- `exact` 条目总数 **≥30 条**（「历史上的今天」的可信度来源）；`period` 条目总数 **≥40 条**（古代文明坐标必须真的存在，不能只有近现代）。
- **每天至少 1 条 `exact`**。若某天确实找不到可核实的真实同日事件，允许该天为 0，但必须在内容评审汇报里**列明是哪几天**——不许为凑数编日期。
- `period` 条目的 `summary` 用正则断言不得命中「`X 月 X 日`」；`exact` 条目的 `summary` 断言必须包含当天日期。
- 当前 90 条的分布：**43 条 `exact`（13 条中华近现代 + 30 条世界）+ 47 条 `period`（全部为中国先秦—清文明坐标）**，30 天每天都有 `exact`。

判定纪律：**凡作者本人不能确信「就是这一天」的，一律标 `period`**，不为版面好看标 `exact`。任何条目都不得为凑当天而改动事件真实日期；查不到可靠年份的选题直接换掉，宁缺毋滥。

## 6. 内容质量与文风

- **三要素齐全**：年份 + 事件 + 一句话文明史意义，缺一不发布。
- **文明史视角**：优先科学发现、技术发明、工程竣工、法典/制度颁布、文化作品问世、重大公共事件；避开帝王家事、宫廷斗争流水账、战争细节、当代政治评价。
- **长度**：`summary` 60–140 字（按 Unicode 码点计），`title` 8–20 字；`summary` 超过 140 字先删修饰，不删事实。
- **文风**：陈述事实，不煽情、不感叹、不使用「最伟大」「彻底改变世界」等夸张断言；不出现「今天我们应该……」式说教。
- **可读性**：一屏可读，避免生僻专名堆砌；数字与年代使用阿拉伯数字（如「1883 年」）。
- **排序权重**：同一天多候选取文明史价值最高者；`weight` 0–100，仅在同日多条时用于排序。

测试断言覆盖（15 项）：

1. 90 条、覆盖 11-18 至 12-17、**每天恰 3 条**、`id` 同日序号恰为 001/002/003 且与月日一致
2. **配比铁律**：每天中华 ≥2 条、世界 ≤1 条；全包中国占比 ≥2/3
3. **世界条目多样性**：欧洲/亚洲/南亚/非洲/拉美/东南亚/大洋洲/阿拉伯板块齐全，**美国题材 ≤5 条**
4. **古今平衡**：中国先秦—清条目 ≥30 条；1840 年后近现代条目 ≤40 条
5. **日期口径**：每条显式合法 `dateKind`；`exact` ≥30 条、`period` ≥40 条；**每天 ≥1 条 `exact`**
6. **日期口径自洽**：`exact` 条目 `summary` 写明当日日期；`period` 条目 `summary` 不得出现公历月日
7. `region` / `origin` 必填且合法，逐条通过 `validateHistoricalEvent`（schema）
8. `license` 白名单（`self-authored` / `public-domain`）与 `source`/`retrievedAt` 齐全
9. `summary` 60–140 字、`title` 8–20 字、`yearLabel` 与 `eventYear` 一致（公元前按「公元前 N 年」）
10. `getEventsForDate` 返回当天 3 条且排序为「中华、中华、世界」，同区按 `weight` 降序、年份升序
11. `getEventForDate` 返回排序后的第一条；无条目日期返回 `undefined`
12. `manifest` 的 counts（90）与数据一致
13. `manifest.files` 的 `bytes` / `sha256` 与数据文件实测值一致
14. `validateContentPack` 精确断言：M0′ 包 errors 恰好 1 条且只能是「hexagrams 64 卦不完整」
15. `assertContentPack` 发布闸门只报卦象缺口，不混入历史事件条目问题

> 第 14 条是哨兵：将来补上卦象后它会主动失败，提醒同步更新测试与 `counts.hexagrams`。

## 8. manifest 更新规则

- `packVersion`：按内容变更幅度递增；M0′ 固定 `0.1.0-m0.0`。
- `counts`：必须等于实际数组长度（`hexagrams: 0` 时不得写 64）。
- `files[].bytes` / `files[].sha256`：**只能由 `scripts/build-manifest.mjs` 计算**，任何手填值都视为不合格。
- `generatedAt`：默认保留既有值以保证可复现；需要更新时用 `PACK_GENERATED_AT=<ISO>` 显式覆盖。
- `coverage.dayOfYearCoverage`：30 天样板为 `partial`，全年补齐后才改为 `full`。

## 10. M0′ 范围说明

- 覆盖 30 天：公历 11-18 至 12-17，**每天 3 条（2 中华 + 1 世界）、共 90 条**，用于验证「当天轮播的古今中外能不能体现华夏文明」。
- 配比硬约束见 §5；`manifest.counts.historicalEvents = 90`，`files[].recordCount = 90`。
- 日期口径见 §5.4：43 条 `exact`（确为当日的「历史上的今天」）+ 47 条 `period`（华夏文明坐标），30 天每天至少 1 条 `exact`；`dateKind` 缺失时 `validate.ts` 报 warning，UI 端按 `period` 降级显示。
- **不含卦象（F08 不在 M0′ 范围）**，`manifest.counts.hexagrams = 0`，`hexagrams: []` 是既定范围而非遗漏。
- 支持范围 1901–2100，展示口径北京时间；内容包内事件的 `eventYear` 可以早于 1901（「历史上的今天」本身就是回看历史）。
- 未来扩到 365 天时：沿用本清单（含 §5 配比），逐日补条目，`dayOfYearCoverage` 改为 `full`，并同步更新 §7 的测试断言。
