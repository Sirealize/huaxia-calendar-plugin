## 二、slot 席位表

### 2.1 契约机制（先搞清"怎么注册"）

- **两段式**：slot 的**所有者**先声明（`children` 声明 = 独占渲染权），**填充者**再 `register` 进去。注册到未声明的 slot 会在**装载期直接抛错**（不是静默失败）；`single` 同格同优先级二次注册、`keyed` 少 `key`、`list` 少 `id` 也都当场抛错。`[类型] @deepseek-ai/dsh-client-ui-slots@0.2.2-rc.1 lib/types/index.d.ts`（`SlotCore.register` 注释：「registering into an undeclared slot throws / missing `key` throws / missing `id` throws」）；`[类型] dsh-client-ui-renderer/lib/types/client/registry.d.ts:95-111`（`inject(key, callback)`：「安装一个 effect，等待该 slot 存在；已声明则同步执行」）
- **注册签名**（`SlotCore.register`，`@deepseek-ai/dsh-client-ui-slots@0.2.2-rc.1` 的 `lib/types/index.d.ts`）：
  - 通用：`name`（目标 slot）、`children`（子 slot 声明）、`store`、`inject`（业务面工厂）、`locale`（文案命名空间）、`registrant`（诊断）
  - 按类型：`single` → 只能一个占用者（同优先级再注册会**抛错**，可给 `priority` 让位）；`list` → 必填 `id`、可选 `order`/`label`；`keyed` → 必填 `key`；`chain` → 必填 `select`
  - 返回值是**幂等 disposer**；disposer 一跑，该条贡献 + 它声明的所有子 slot 一起塌缩（"一条生命周期轴，没有悬挂状态"）。
- **生命周期**：`ctx.effect(() => ctx.slots.register(...), 'label')` 把注册绑到**插件自己的 fiber**；插件停用/卸载时 cordis 自动跑 disposer，无需手写 teardown。`[文档] dsh-client-ui-sidebar/README.zh.md:42`、`[文档] dsh-client-modules/README.zh.md`（「停用会移除条目，并在其异步 effect 完成清理后回收未使用的模块与样式」）。
- **真实写法**（从**第三方**插件 `dsh-context` 反编译确认，`~/.dsh/profiles/web/node_modules/dsh-context/lib/client.js`）：
  ```js
  ctx.slots.inject(`main`, () => ctx.slots.register({ name:`main`, key: PANEL_ID, locale: NS }, Panel))
  ctx.slots.inject(`sidebar.panellist`, () => ctx.slots.register({ name:`sidebar.panellist`, id: PANEL_ID, order:20, label:()=>t('title') }, Icon))
  ctx.slots.inject(`sidebar.right.pane.tab`, () => ctx.slots.register({ name:`sidebar.right.pane.tab`, key: tabId }, Body))
  ```
  它同时注册了 `main` / `sidebar.panellist` / `sidebar.right.pane.tab` / `conversation.view` / `conversation.input.overlay` / `plugins.bundle.config` —— **第三方接管主面板是既有能力，不是我们的一厢情愿。**
- **作用域决定能拿到什么 hook**（这条最影响日历设计，`[类型] dsh-client-ui-session/lib/types/client/index.d.ts:72-97`）：
  - `root` 作用域组件拿到 `useSessions` / `useSessionStatus` 等「全局座」
  - `session` / `session-maybe` 作用域组件**额外**拿到 `useSession` / `sessionId` / `useProjection`
  - 所以 **`main` 面板（root 作用域）拿不到当前会话的 `useProjection`**，读 Token 要改用 `useSessions()` 返回的列表快照（见第五节）。

### 2.4 推荐主形态（回应"今日一屏"需求）

结合内容层的结论（历史叙事须自撰、不宜做长列表；UI 重点应是"今日一屏 + 月历"）：

| 形态 | 席组合 | 为什么 |
|------|--------|--------|
| **主形态：全局面板**（推荐） | `sidebar.panellist` + `main` | 空间最大，能放"月历 + 今日一屏"上下分栏；和「插件」页同构，用户认知成本低；`dsh-context` 已证明第三方能这么干；root 作用域不需要会话，hero 页也能进 |
| 轻形态：常驻浮标 | `shell.overlay` | 不抢任何人的位置（additive list），点击穿透不挡聊天；适合"每天扫一眼"的 F04 悬浮形态；但**不是 OS 级置顶**，F11 的四角拖拽/置顶仍要 Tauri 兜底 |
| 可选：整宽横条 | `shell.bottom` | 席位**空闲**，天生适合"一屏并列"；代价是永久压缩三列高度，必须做成可收起，否则用户会关掉 |
| 不推荐：右栏 | `sidebar.right.pane.tab` | 无会话首页直接缺席（`[文档]` 明确限制），与"每天开工先看一眼"的 S1 场景冲突 |

**结论**：MVP 做「`sidebar.panellist` + `main` 全局面板」为唯一主入口，`shell.overlay` 做可开关的常驻浮标；`shell.bottom` 留到 M1 做"一屏对比"实验。

## 三、构建链可行性与所需依赖

### 3.1 产物契约（唯一硬约束）

客户端插件的浏览器半侧不是普通 ESM，而是**模块加载器 bundle**：

```js
window.__ModuleLoader__.load({
  id: "dsh-hello-huaxia",
  factory: (require) => { var module = {exports:{}}, exports = module.exports; /* … */ return module.exports }
})
```
`[公开源码] packages/client/tsdown.client.ts:1-8`（"Emits a closure-factory artifact: the bundle calls window.__ModuleLoader__.load({id, factory, meta}) and resolves externals through the injected require"）；`[文档] dsh-client-modules/README.zh.md:34,56,58`。
`require` 只能解析到宿主**冻结的平台模块表**，超出基座的要写进 `package.json` 的 `dsh.client.external`：

```
PLATFORM_MODULES = [
  'react', 'react/jsx-runtime', 'react-dom', 'react-dom/client', '@deepseek-ai/cordis',
  'zod', '@tanstack/react-virtual', '@deepseek-ai/dsh-client-store',
  '@deepseek-ai/dsh-client-ui-slots', '@deepseek-ai/dsh-client-ui-primitives',
  '@deepseek-ai/dsh-client-ui-dockkit',
]
```
`[公开源码] packages/client/web/src/platform.ts:8-19`；`[实测]` 构建出的前端 bundle 里同一张表（`/Users/wanghongmei/dsh-022/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-*.js` 中的 `staticModules`）。**注意 `react` 是宿主提供的，插件不该打包自己的 React。**

## 四、安装与离线分发可行性

### 4.1 profile 与组合模型（读完 `~/.dsh` 只读确认）

```
~/.dsh/profiles/web/
├── package.json        # dependencies（pnpm 管）+ dsh.profile.bundles（有序层清单）
├── cordis.yml          # 永远是 []，注释明确「Edit cordis.patch.yml, not this file.」
├── cordis.patch.yml    # 用户自己的 patch 层（最后应用）
├── pnpm-workspace.yaml # nodeLinker: hoisted / autoInstallPeers: false / allowBuilds
└── node_modules/
```
用户当前 web profile 的 `dsh.profile.bundles` 里有 9 个 bundle，其中 **5 个是第三方包**（`dsh-context`、`dshmarket`、`dsh-whale-widget`、`@iasiv5/dsh-skins`、`@wxg-prc-cpg/browser-skill-dsh-plugin`）——**第三方插件安装是既成事实，不需要我们证明能不能装，只需要证明装法**。`[实测] cat ~/.dsh/profiles/web/package.json`

层顺序（`[文档] github.com/deepseek-ai/deepseek-harness docs/user/develop/basic/publish.zh.md`「加载顺序」）：`dsh.profile.bundles` 顺序 → profile 的 `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → 每个 `--patch`。后应用者按行胜出，且 **patch 替换整行 config 而非深合并**。

### 4.2 三种安装来源（都在隔离 `DSH_HOME` 里实测）

| 来源 | 命令 | 实测结果 | 适合 |
|------|------|---------|------|
| 本地 tarball | `dsh plugin --profile <p> add ./pkg-0.0.1.tgz` | ✅ 装成功；`dsh.profile.bundles` 自动追加包名；`--dump-config` 出现 `# == dsh-hello-huaxia` 层 | **内网/离线首选**（把产物打进 tgz，零构建、零网络） |
| npm 包 | `dsh plugin --profile <p> add <pkg>@<ver>` | 同机制（用户 profile 里的 5 个第三方插件即此路径） | 公网首选 |
| **git URL** | `dsh plugin --profile <p> add git+file:///…#<sha>`（实测用本地 git 模拟 `github:you/repo#sha`） | ⚠️ **第一次必失败**：`ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`；把 pnpm 打印的精确 key 加进 `pnpm-workspace.yaml` 的 `allowBuilds` 后**成功**，`prepare` 脚本执行、bundle 层生成 | 源码分发/内网 git 镜像；**不能承诺"3 条命令无脑装"** |

`[实测]` git 失败原文（摘）：
```
[ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED] Failed to prepare git-hosted package … needs to execute build scripts but is not in the "allowBuilds" allowlist
allowBuilds:
  "dsh-hello-git@git+file:///tmp/huaxia-spike/gitdemo#65793c7…": true
dsh: git-hosted plugins build on install via their prepare script, which pnpm blocks until allowed — add the exact key pnpm printed above under allowBuilds in …/pnpm-workspace.yaml, then re-run
```
这正是官方文档 `[文档] publish.zh.md`「从 GitHub 安装：构建脚本这道坎」写的两道门槛：**作者要提供自包含 `prepare`（不能假设旁边有 monorepo checkout）+ 用户要显式授权安装期执行代码**。文档同时给了免授权路径：**发 npm（发布前构建好 `lib/`）或交付 tarball**。

### 4.3 版本兼容校验（实测，会直接影响发布策略）

`[实测]` 造了一个 `engines.dsh: ">=9.0.0"` 的包，安装时被拒：
```
dsh: installation rejected: Plugin dsh-hello-engine@0.0.1 is incompatible with dsh 0.2.2-rc.1:
requirements {"engines.dsh":">=9.0.0"} … 
dsh: restored package.json, pnpm-lock.yaml, and node_modules.

```
即：**不合规会硬拒且回滚**，有显式豁免入口。另有第三方写法 `dsh.compatibility.dshReleases`（见 `dsh-context` 的 `package.json`：`"0.2.2-rc.1+": "compatible"`）。

**注意一条文档/实现不一致**：`[文档] dsh-package-manifest/README.zh.md:96` 说「当前安装器和加载器不强制检查 `engines.dsh`」，但 **实测安装器强制检查**。以实测为准，并保守假设**加载器**可能不查（未验证启动期行为）。

### 4.4 离线可用性结论（F06）

| 场景 | 结论 |
|------|------|
| 插件**运行时** | ✅ 全离线成立。客户端 bundle 由本机宿主从磁盘提供（`/plugins/<id>/client.js`），不联网；农历/节气/卦象只需本机算法，无 API 调用 |
| **安装** | ⚠️ 分路径：tarball / npm 离线缓存 / pnpm store 复用 → 可离线；`git+https` 首次安装需网络拉源码，且 `prepare` 常需 devDeps（node_modules）→ 内网需预置 |
| **升级** | tarball 换版本重装 / `dsh plugin add` 本地路径；git 渠道 `git pull` + 重装（仍需 allowBuilds 已授权） |

**对 F05 的最终建议**：把「Git 地址一键安装」降级为「**git 是三种分发渠道之一**」，主推 **tarball（内网）+ npm（公网）**；git 渠道在 README 里写清 4 步（含一次失败重试与 `allowBuilds` 授权），并**把 commit sha 锁死**（官方文档明确提示：不锁 sha 则后续推送可悄悄改变实际运行内容）。

## 五、Token 数据可得性

### 5.1 结论：能自动读，含输入/输出/缓存四桶

`[类型] dsh-token-meter/lib/types/projection.d.ts:8-20`：
```ts
export interface TokenUsageProjection {
  uncachedInputTokens: number
  outputTokens: number
  cacheReadTokens: number
  cacheWriteTokens: number
}
```
`[类型]` 同文件 `:63-72` 把它注册进 `SessionProjectionMap` 的 `tokenUsage` 键，并且**只有 `contextPressure` / `contextBreakdown` 带 `SessionProjectionSummaryExcluded` 标记，`tokenUsage` 没有** → 说明它**进入 session 列表摘要**（`[类型] dsh-session-projection/lib/types/types.d.ts:56-64`：摘要 = 全部视图值减去被排除键）。
`[文档] dsh-token-meter/README.zh.md:49`：「token-meter 通过必需的 `ctx.sessionProjections` 服务注册三个客户端投影单元和一个仅供宿主使用的单元……`tokenUsage` 携带完整持久日志中的 4 个桶」。

**默认 Web 组合里这些已经挂载**（`[实测] DSH_HOME=/tmp/… dsh --profile web --dump-default-config`）：`session-projection`(行 93)、`token-meter`(行 272)、`session-stats`(行 452)、`session-controller`(行 457) —— 不需要用户自己装。用户实际 profile 的 `cordis.patch.yml` 只改动了 `remote-web-ui`（禁用）、`browserskill`、`ui-settings-general`、`ui-theme`、`web`、`dsh-context` 这几行，**没有禁用任何 token/统计行**（`[实测] cat ~/.dsh/profiles/web/cordis.patch.yml`），所以默认组合的投影在本机是活的。

### 5.2 三条读取路径

| 路径 | 能拿到什么 | 限制 | 证据 |
|------|-----------|------|------|
| **A. 组件内 `useProjection('tokenUsage')`** | 当前会话的 4 桶累计值（宿主算好、schema 校验过的整值） | **只有 `session`/`session-maybe` 作用域的 slot 组件有这个 hook**；`main`/`shell.*`（root 作用域）没有 | `[类型] dsh-client-ui-session/…/index.d.ts:80-97`；`[类型] dsh-api-session-controller/…/projection-store.d.ts:28-32` |
| **B. 组件内 `useSessions(selector)`** | `SessionListState` = `{ ids, byId, phase, projectionsBySession }`；每行 `SessionSummary` 带 `updatedAt` 与 `projectionValues`（摘要值，含 tokenUsage） | 投影是**整会话累计**，不是按天；跨天会话要按 `updatedAt` 归属或再拆 | `[类型] …/sessions/service.d.ts:50-60`（`SessionListState`）、`:43-46`（`projectionValues`）、`…/sessions/lineage.d.ts:13-36`（行级 `updatedAt`） |
| **C. 宿主半侧 `ctx.tokenMeter` / `ctx.sessionQuery`** | 精确：`ctx.tokenMeter.measure(session)` 拿当前会话；`ctx.sessionQuery.listSessions()` + `readSession(id)` 读**完整事件日志**（assistant 消息里带 provider 上报的 usage）→ 可按**每条事件的真实时间戳**聚合"按天" | 需要把聚合结果自己落到本地存储（离线、无后端，正好可以做 IndexedDB/JSON 文件） | `[文档] dsh-token-meter/README.zh.md:36-40`；`[文档] dsh-session-query/README.zh.md:32-45`（`listSessions`/`readSession`/`listEvents`） |

### 5.3 "按天聚合"的唯一缺口

`tokenUsage` 是**整会话累计**（4 桶求和），投影层面**没有按天切分**。要做"日历上每天显示当日消耗 + 月视图汇总"，必须二选一：

1. **客户端近似**（MVP 够用）：`useSessions()` → 每个会话按 `updatedAt` 归到某天 → 该天求和。跨天会话会被整体记到最后活动日。
2. **宿主半侧精确**（M1 做）：插件同时提供宿主半侧（`lib/index.js`，本来就是 bundle 的两半之一），用 `ctx.sessionQuery.readSession()` 折每条 assistant 事件的 usage + 时间戳 → 按本地时区分日 → 写自己的本地存储。**这是自动采集的满血形态。**

> 另有一个现成参照：`dsh-experimental-client-ui-stats` 的「统计」页签已经在做每轮/每步 token、缓存命中率、TTFT 的展示（`[文档] dsh-experimental-client-ui-stats/README.zh.md`），证明这些数在客户端**确实可读可用**，不是纸面 API。

### 5.4 对 F07 的建议

- 规划 A4/F07 的默认假设是「手动录入 + CSV 导入」。**建议直接改成：自动采集（默认）+ 手动补录（兜底）**。手动录入仍然保留，但定位从"唯一来源"降为"补录/校准"。
- 数据全部留在本机（投影与日志都在本机），符合 A6「纯本地」，无隐私外发。
- 展示层建议：`main` 面板用 `useSessions` 聚合（root 作用域可行），不用为了 `useProjection` 去受右栏的"无会话缺席"限制。
